# Contributing

Thanks for helping improve the Atlas3 clients. This repository contains two
aligned packages; a change to one usually needs a matching change to the other.

## Ground rules

* **ATLAS 3.0+ only.** Do not add WebAPI 2.x compatibility shims.
* **No credentials in the repository.** Never commit API keys, JWTs, passwords,
  or captured `X-API-KEY` headers.
* **Keep the public surfaces aligned.** If you add a method to one client, add
  the equivalent method to the other and update `docs/parity.md`.
* **Prefer the API over scraping.** The clients speak JSON to WebAPI; they do
  not parse the ATLAS UI.
* **Be kind.** See `CODE_OF_CONDUCT.md`.

## Development setup

### Python

```bash
cd python
python -m venv .venv
. .venv/bin/activate
python -m pip install -U pip
python -m pip install -e ".[dev,circe,keyring]"
pytest
ruff check .
mypy src
```

### R

```bash
cd r
Rscript -e 'install.packages(c("devtools", "roxygen2", "testthat", "httr2", "jsonlite", "checkmate", "R6"))'
Rscript -e 'devtools::document()'
Rscript -e 'devtools::test()'
R CMD build .
R CMD check --no-manual Atlas3_0.1.0.tar.gz
```

Do not edit `NAMESPACE` or `man/*.Rd` by hand; they are generated by roxygen2.

## Integration tests

The integration suites exercise a real ATLAS 3.0 deployment. They are opt-in:

```bash
export ATLAS3_TEST_URL="http://localhost:8081"   # ATLAS UI URL or /WebAPI URL
# Set ATLAS3_TEST_API_KEY in your shell or secret manager; do not commit it.
export ATLAS3_TEST_SOURCE="EUNOMIA"

cd python && pytest -m integration
cd r && Rscript -e 'testthat::test_local(filter = "integration")'
```

Tests create resources with a random suffix and delete them in `finally` /
`on.exit`. They must never modify seeded demo cohorts or concept sets.

The reference stack used by maintainers is:

```bash
# ATLAS 3 UI + WebAPI 3 + PostgreSQL (OHDSI images)
docker compose -f examples/docker-compose.atlas3.yml up -d
```

## Adding an endpoint

1. Capture the method, path, parameters, body, and response from WebAPI 3.0
   (source or `/WebAPI` behavior). Do not guess.
2. Add a typed method if the endpoint belongs to a core resource; otherwise use
   the generic `request()` / `call()` surface.
3. Add the endpoint to `scripts/endpoints.yaml` if it is missing, then run
   `python scripts/sync_endpoints.py` to regenerate both catalogs.
4. Add a unit test for path/parameter handling. Add an integration test only if
   the endpoint is safe to call repeatedly.
5. Update `docs/endpoints.md` and `docs/parity.md`.

## Commit and PR conventions

* Small, focused commits with imperative subjects.
* Update `python/CHANGELOG.md` and `r/NEWS.md` for user-visible changes.
* CI must pass on Linux and macOS for both packages.
* A maintainer reviews API shape changes before merge.

## Releasing

Python: bump `python/pyproject.toml` and `python/src/atlas3/_version.py`, tag
`python-vX.Y.Z`, build with `python -m build`, publish with `twine`.

R: bump `r/DESCRIPTION`, run `R CMD check --as-cran`, submit the tarball to
CRAN, tag `r-vX.Y.Z`.
