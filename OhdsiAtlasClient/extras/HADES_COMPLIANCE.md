## WebAPI dependency: the one open decision

HADES states:

> There should be no two HADES packages that provide the same functionality. For
> example, all communication with `WebAPI` should go through `ROhdsiWebApi`.

`ROhdsiWebApi` supports **WebAPI 2.x**. It does not support ATLAS 3.0: the
endpoints, the authentication model (personal API keys instead of
database/AD/Windows credentials), and the resource shapes changed. A client for
ATLAS 3.0 cannot be built on it.

**The intended resolution is succession, not duplication.** `OhdsiAtlasClient`
is the replacement for `ROhdsiWebApi` on ATLAS 3.0:

* `ROhdsiWebApi` remains the supported client for ATLAS 2.x. It is not being
  withdrawn, and existing scripts continue to work against ATLAS 2.x
  deployments.
* `OhdsiAtlasClient` is the client for ATLAS 3.0 and later.
* `vignette("migrating-from-rohdsiwebapi", package = "OhdsiAtlasClient")` maps
  every commonly used `ROhdsiWebApi` function to its replacement, so users move
  when they upgrade their ATLAS instance rather than being stranded.

The two packages therefore never target the same server version. This is the
same pattern HADES already uses for major-version transitions elsewhere.

**What is still required:** the HADES steering group needs to record that
`ROhdsiWebApi` is in maintenance for ATLAS 2.x and that `OhdsiAtlasClient` is
the designated successor for ATLAS 3.0+. Until that is minuted, this package
formally conflicts with the "all WebAPI communication through `ROhdsiWebApi`"
rule, even though it does not duplicate `ROhdsiWebApi`'s functionality in
practice.

We deliberately do **not** add `ROhdsiWebApi` to `Suggests` or `Imports` to
satisfy the letter of the rule: it is not on CRAN, it cannot talk to WebAPI
3.0, and a dependency that only exists to satisfy a checklist would add
instability without adding function.

## How compliance is verified

```bash
cd OhdsiAtlasClient

# Documentation and spelling
Rscript extras/PackageMaintenance.R

# Tests and coverage (HADES guideline: ~80%)
Rscript -e 'covr::package_coverage(type = "tests")'

# Check as CRAN would
Rscript -e 'devtools::check(args = c("--no-manual", "--as-cran"), error_on = "warning")'
```

CI runs the same checks on all three platforms and fails below 80% coverage.

## Deviations and notes

* **`Config/testthat/edition: 3`** is set. Tests for internal functions use
  `OhdsiAtlasClient:::` deliberately; the package's public surface is thin, and
  testing internals directly is more honest than exporting them.
* **`keyring` is a `Suggests`, not an `Imports`.** Credential storage falls back
  to a `0600` file when no keyring is present, so the package installs and runs
  without it.
* **`httpuv` is not a dependency.** The test suite does not open a socket; it
  replaces the single HTTP transport seam with an in-process fake, so tests are
  fast, hermetic, and run in CRAN's restricted environment.
